# Webnox OS — developer notes

Product: Webnox OS (multi-tenant SaaS). Repo: `webnox-os`.
Stack: plain HTML/CSS/vanilla JS modules, one Express file (`server.js`), Supabase, Vercel. No React, no bundler.

## Decisions that override the docs
- Product name is **Webnox OS** (docs say Webnox Hub).
- Master sign-in route is **`/master-signin`** (docs say `/master-login`). The "no link anywhere" rule applies to this string.
- Up to **3 Master accounts** (docs say one). `promote_to_master()` refuses a 4th. Master notices go to all Masters. Access/payment logs record which Master acted.
- Space types: **Personal (non-rented)** and **On rent** (docs: master_project / rented).
- Master theme: dark navy with cyan-to-indigo gradient (from owner's screenshot), not light blue. Business workspaces stay white.
- First Master email: Webnoxhub@gmail.com.

## Conventions
- Vercel runs `api/*.js` as functions and serves `public/**`; `server.js` is for local dev only (`npm run dev`).
- Every Master API route starts with `requireMaster(req)` from `lib/master-guard.js`.
- Dates are shown in Asia/Karachi (`js/time.js`). Money shown in PKR (base currency).
- The string `master-signin` may appear only in `public/master-signin.html`, `public/robots.txt`, `vercel.json`, `server.js` and `AGENTS.md`. `tests/static.test.mjs` enforces it for `public/`.
- `app.html` and `login.html` never contain the word "Master"; the Master UI is built by JS only for a Master.
- Not built yet: workspace creation (M4), branded business login (M5), Master finance, billing sweep, everything inside a business workspace.
- **Phase 3 (Leads + Clients)** — `supabase/schema.sql` PART 13 (per-workspace `role_permissions`, `perm()`/`pm_perm()` gated by the Master's role switches, `leads`, `clients` with per-workspace BUID, `client_files` + `client-files` bucket at `<workspace>/<client>/<file>`, `lead_convert`), `public/js/eco/pages/leads.js` + `clients.js`, public lead form `/lead-form.html?t=<workspaces.public_form_token>` served by `api/public/form.js` + `api/public/lead.js` (`lib/public-form.js`). `clients.js` has `INVOICES_READY` / `PROJECTS_READY` flags and `eco/invoices.js` is a placeholder until Finance/Projects land.
- **Phase 4 (Projects)** — `supabase/schema.sql` PART 15: bigint `projects`, `project_members`, `project_requirements`, `staffing_requests` (+ `_items`, `request_comments`), `tasks.project_id`, `client_files.project_id`; staffing flow as RPCs (`staffing_request_create/decide/comment`, `project_member_add/remove`, `project_candidates`, `agent_fits`) that write English activity lines + notifications; `projects` module in `role_permissions`; storage path `<workspace>/<client>/p<project>/<file>`. First-version uuid projects are moved across once. Old `api/projects.js`, `api/inbox.js`, `lib/project-rules.js`, old pages and the `activity_log` table are gone. UI: `public/js/eco/pages/projects.js` + `project.js` (7 tabs + Team). `INVOICES_READY` stays false in `project.js` / `clients.js` until Phase 5.
- Phase 5a (Finance + Invoices + Permissions page): PART 16, tests/finance.test.mjs, pages/finance.js, invoices.js, pages/permissions.js. Billing page deferred to M18.
- **M17 (Master Finance)** — `supabase/schema.sql` PART 17: Master notices (`notifications.workspace_id` now nullable; null = a notice for the Masters), `master_today()` / `master_due_date()` / `is_trial_cycle()`, `notify_masters()` + `notify_ws_admins()`, `master_record_payment()` (advances the cycle, ends a trial, lifts a money-only hold, logs and notifies), `master_change_plan()` (takes effect from the next due date, never rewrites past payments), `master_sweep()` (daily trial countdown, 3-day warning, due today, daily overdue, auto-hold once the grace days are over; personal spaces are skipped), `master_overview()`, `master_report()`. UI: `public/js/pages/master-finance.js` — four tabs (Dashboard / Subscriptions / Payments / Reports), record payment, change plan, hold and resume (through the existing `/api/master/workspace` PATCH), CSV and print. `app.js` wires the Finance nav item; `app.css` gains `.tabs`, `.statline`, `.bars` and a print block. `tests/master-finance.test.mjs` plays a whole rent cycle on frozen dates. Workspace Billing page and rent invoices are still M18.
- **M18 (Rent invoices + workspace Billing)** — `supabase/schema.sql` PART 18: `master_counters` (one platform-wide counter, `INV-WX001` onward, never reused), `rent_invoices` (money trigger, cascades from `workspaces`), `master_issue_rent_invoice()` (every field defaults from the plan; one open invoice per period), `master_void_rent_invoice()` (a paid invoice cannot be voided; the reason is kept), `settle_rent_invoice()` — called from `master_record_payment()`, so a recorded payment closes the oldest open invoice on its own. RLS: Master everything, workspace Admin reads their own (and still can while on hold); ordinary members see nothing. `master_access_log` gains `invoice_issued` / `invoice_voided`. Also fixed from M17: Master notices used `fmt_money()`, which reads the *current workspace's* currency — a Master has none, so it said USD. New `money_text(currency, amount)` / `master_money(amount)` replace it.
- **M18 UI** — `public/js/invoice-css.js` holds the invoice stylesheet (`eco/invoices.js` now imports and re-exports it) so the rent invoice is the same paper as a workspace's own. `public/js/rent-invoice.js` draws it with Webnox as the issuer and the workspace as the billed party, and prints through a hidden frame; it imports nothing from either world. `public/js/eco/pages/billing.js` is the workspace Billing page (plan, invoices with preview + print + CSV, payments). `eco/shell.js`: `billing` is owner-only nav, and `start({ held })` strips the shell to Billing alone. `app.js`: a suspended workspace no longer signs everyone out — the Admin gets in and lands on Billing, members still get `?m=closed`. `master-finance.js` gains an Invoices tab (filter, preview, cancel) and Issue invoice in the Manage modal. `tests/billing.test.mjs`. Rent invoices are not emailed: the app still sends no mail.
